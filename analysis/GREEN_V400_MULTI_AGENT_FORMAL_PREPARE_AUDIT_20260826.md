## Reviewer 1 — mathematical and theorem-chain audit

**Decision: BLOCK development; GO only for outcome-blind formal remediation.**

The mathematical skeleton is credible: the branch contrast is `PAT_J - PAT_B - TAR_J + TAR_B`; the second-order jet recurrences, signed curvature weights, endpoint signs, and central witness correction agree with the intended theorem. The problem is not a downgrade of the paper's theoretical thesis.

The implementation does not yet establish that the theorem is being applied to the actual Transformer computation. The emitted graph is a coarse template rather than a replayable exact relational DAG, and the tests advertised as end-to-end Transformer tests do not contain genuine layer normalization, causal attention, softmax, or unembedding contrast. Consequently the formal theorem is currently connected only to synthetic scalar graphs.

Required mathematical closure: a replayable row specification, exact graph serialization, a genuine tiny Transformer oracle, and graph-to-model parity tight enough to prove semantic equivalence rather than merely numerical scale agreement.

## Reviewer 2 — numerical and certificate-backend audit

**Decision: BLOCK real certificates and development; GO for backend repair.**

The MPFR/interval scalar core is useful and the existing 70 tests are real, but several production claims are not implemented:

- `RelationalGraph.evaluate` cannot execute the Transformer operations listed in the coverage artifact.
- FMA/pairwise primitives are not wired into production reductions.
- Softmax pivoting does not preserve the exact shared-zero identity strongly enough, and layer-normalization variance misses nonnegative-square tightening.
- `certify_joint_witness` uses only two fixed cells, ignores tolerance-driven subdivision and `max_depth`, performs no multi-radius intersection, and does not run the required 384/512 nesting audit.
- Resource/partition validation is insufficient.
- HF/TransformerLens parity is not graph parity; the recorded tolerance is orders of magnitude too loose relative to the observed error.

Required numerical closure: schema-driven execution with no silent defaults, adaptive exhaustive dyadic partitions, multi-radius intersection, full precision nesting, rigorous resource limits, and graph/HF/TL three-way parity.

## Reviewer 3 — protocol, provenance, and leakage audit

**Decision: BLOCK authorization; scientific one-shot remains unspent.**

The run preserved important protocol boundaries: the repository history is clean relative to the binding parent; formal/development/confirmation row hashes are disjoint; execution flags are false; and failed attempts did not expose scientific outcomes. Token-shape and causal-mask repairs were outcome-blind and are retrospectively admissible engineering fixes.

However:

- `graph_manifest.jsonl` contains repeated hand-written edges, operation names, constant node estimates, and hashes of metadata rather than a serialized executable graph.
- `certificate_plan.jsonl` cannot round-trip through `CertificatePlan.from_dict`; the executor then silently substitutes missing fields.
- sealed confirmation identifiers are imported in plaintext for exclusion, while the audit claims they were unopened.
- the independent audit validates counts and self-reported PASS booleans but does not rebuild/replay graphs, round-trip plans, verify implementation coverage, or inspect the sealed-ID import boundary.

Required protocol closure: salted-hash-only exclusion, exact schema round-trip, replay-based audit, implementation-derived coverage, immutable versioned remediation artifacts, and continued prohibition on all real outcomes.

### Lead-auditor integration addendum

The remediation cross-check found one further blocker at the same boundary. The current donor feasibility loop hashes raw clean/corrupt cache differences at three hooks, but it does not yet serialize the fresh v4 held-out direction panel, a complete four-branch PAT/TAR × joint/bypass record, or the exact repository hook ordering used by the path target. Those hashes therefore do not yet identify the scientific intervention that the theorem is meant to certify. This is still outcome-blind and consumes no scientific trial, but exact direction/branch serialization and a composition-identity test are required before graph extraction can be considered meaningful.

All three reviews agree on the decisive distinction:

1. **Theory is not rejected.** The main scientific idea and scalar theorem chain remain viable.
2. **The prior formal PASS overstates implementation readiness.** It demonstrates a sound scalar prototype and package consistency, not an executable formal certificate for the real GPT-2 relational graph.
3. **No scientific trial was consumed.** Because no true endpoint/derivative/outcome certificate was run, remediation can proceed without contaminating development or confirmation.
4. **No GPTPro dependency is necessary for this stage.** The blockers are concrete, testable engineering/scientific-integration defects that can be repaired locally and re-audited independently.
